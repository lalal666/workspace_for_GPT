# 跨端协作与设备生命周期

按本期场景选用相应条目。先画出或写出实际拓扑，标明设备与固件、微信小程序、云端、可选的网关或父节点及第三方设备之间的控制流和数据流。给出本地链路与云端链路各自的可用前提。

## 联动、控制与状态

| 要定义的事项 | 需要在 PRD 中写清的行为 |
| --- | --- |
| 对象与边界 | 项目、空间、分组、设备和控制对象的关联与权限。批量控制要定义目标清单的确定时点、部分成功、失败对象及后续操作。 |
| 策略与仲裁 | 本地按键、小程序、定时、感知、云端调度和设备保护等来源中，哪些适用。定义并发冲突、手动接管及有效期、恢复自动的时机，以及保护条件触发后的行为。优先级由产品和安全约束确定。 |
| 指令生命周期 | 按可观测阶段定义云端受理或排队、送达或设备确认、物理动作或状态核验。注明证据来自哪一端、超时起止点、指令有效期、重复指令处理和重试条件。对可能重复触发实体动作的命令，写清重试后的行为。 |
| 状态和交互 | 区分目标状态、设备回报、外部实测及推断状态。明确显示来源、时间和数据过期后的提示。无双向状态反馈的红外控制，定义「已发射」「推断」「未知」等可验证口径，以及恢复可信状态需要的证据。 |
| 联动恢复 | 按本期风险考虑设备休眠、网络或云端中断、父节点掉电、恢复供电、重连、时钟失准和数据陈旧。每种情况写明现场可保留的功能、各端显示、过期指令处置、状态对账、告警和恢复条件。 |

微信小程序需求跟随用户任务写。若小程序承担批量配置、扫码绑定、远程控制或运维诊断，明确操作角色、所需权限、目标设备和结果反馈，并写明拒绝、离线、处理中以及部分成功等状态。出现离线或异步执行时，刷新和重新打开页面应采用项目定义的状态来源与时间口径。

## 物模型与接口

- 优先复用已确认的物模型与事件定义，引用精确版本及适用 SKU。按实际需求列属性、事件、服务或命令，以及来源、消费方、数据类型、单位、有效范围、精度、读写权、配置生效条件、错误码或缺失值语义。物模型字段与小程序展示、控制和告警的映射应能核对。没有相关能力的 SKU 要定义入口、数据与配置处理。
- 分别定义采样、事件触发、数据上报与显示更新。需要时写明触发阈值、抖动抑制、心跳、休眠接收窗口、告警优先级和平台容量，并在链路条件下校验时延能否实现。
- 区分事件发生时间、系统接收时间和界面更新时间。涉及计费、统计、调度或恢复补报时，约定时间基准、准确性与失准标记，明确历史事件是否参与实时联动和节能报表。定义事件去重键、乱序处理和确认边界，考虑重启、序号回绕与重复补传。
- 适用时定义设备缓存的容量或覆盖工况、断电保留、满载淘汰、过期、补报顺序、限流和终止条件。核对实时事件、补报、批量配置及升级能否共存。协议字节布局、API 请求体和算法细节可链接至对应规格，由 PRD 给出已确认约束和外部可观察行为。

## 从生产到退役

| 阶段 | 按范围核对 |
| --- | --- |
| 生产与建档 | SKU 与硬件版本、唯一身份、标签或二维码与后台映射、授权凭据交付、产测和校准记录。引用已确认的编码规则。 |
| 部署与调试 | 安装、上电或出运输模式、入网、绑定、分组和场景调试。若跨近场和云端，说明权限、失败后从哪一步恢复，以及重复提交的结果。 |
| 运行与运维 | 设备状态、告警、记录、现场诊断权限和数据归属。涉及人员活动或环境数据时定义业务用途、可见角色、保留与删除要求。定义授权边界和敏感操作的审计证据。 |
| 升级与兼容 | 如支持 OTA，定义适用 SKU 和硬件、固件、云端、接入节点与小程序版本，升级前提、灰度、进度和失败状态、断电或断网时恢复、回滚或现场恢复路径。说明升级期间是否允许控制以及配置、绑定和历史数据如何处理。 |
| 解绑与换机 | 说明重置、解绑、转移、换机和退役时设备身份、分组、策略、凭据和数据的保留、迁移或清除条件。定义未授权控制的拒绝行为。 |

## 写法示例

假设某会议室方案采用独立存在传感器及调光灯具，需要定义「掉线恢复后会不会被历史事件误触发」。在草稿中可提出：若本期确认由本地策略执行照明联动，断云期间本地感知和调光按现行策略运行。云端恢复后可将早于有效窗口的补报事件纳入历史记录，并按规则禁止它触发当前调光。有效窗口和时钟失准处理由方案负责人确认。验收分别观察断云时的灯具实际动作、恢复后的事件时间及历史记录、是否新增控制动作。方案采用的拓扑、策略位置与有效窗口均随项目决议填写。
