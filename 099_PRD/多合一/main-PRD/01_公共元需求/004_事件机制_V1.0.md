# 004_事件机制

# 01 术语表

| 术语              | 本文含义                                  |
| --------------- | ------------------------------------- |
| LPN             | 接入澜潮现场网络的低功耗节点，本文主要指多合一传感器。           |
| 事件              | 满足规定条件时生成的一条记录，例如确认有人、欠压预警或配置生效。      |
| 状态快照            | 设备在某一时刻的状态和读数，用于查看人员存在状态、照度或电量等信息。    |
| 事件编号（`eventId`） | 标识一次实际发生的事件。同一事件重发、补报或换父后重新发送时，沿用原编号。 |
| 回执              | 接收方返回的确认消息。灯具收件、父节点接管和云端入库各有对应的确认结果。  |
| 补报              | 链路恢复后，把中断期间未送达的记录按原发生时间发出。            |

# 02 需求边界

## 2.1 适用范围

1. 本 PRD 作为多合一 LPN 产品的公共元需求，定义事件产生、本地通知、上报确认、配置生效及异常恢复。各型号的主 PRD 确定适用事件、具体触发条件和验收指标。
2. 本地组网或小程序扫码组网完成后，LPN 使用同一套事件机制。父节点、网关、云平台和执行端按各自在事件链路中的职责参与。
3. 入网鉴权、链路保护和低电运行限制分别参照对应子 PRD。[003 组网与鉴权](003_配网与鉴权_V1.0.md) · [002 通信与安全](002_通信与安全_V1.0.md) · [001 LPN 能源管理](001_LPN能源管理_V1.0.md)

## 2.2 前置条件

1. LPN 完成入网鉴权后投递正常业务事件。现场联动使用已生效的规则、获授权的目标组和可用的现场链路。
2. 云端入库依赖现场网络到云平台的上行链路。中断期间按 3.4 暂存，恢复后补报。
3. 本 PRD 的需求大类为 5，编号为SR-5XXX。

# 03 具体阐述

## 3.1 事件产生

| ID      | 需求描述                                                                                                                                        | 优先级 | 对应领域            |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --- | --------------- |
| SR-5101 | 1）**按明确条件产生事件。** 各型号根据有效采样、状态变化或实际操作结果定义事件的触发及恢复条件。<br>2）状态变化事件在满足条件时记录一次。持续维持同一状态时，按该型号约定更新快照、做周期统计或发出有独立触发条件的提醒。                          | P0  | FW、产品、TE        |
| SR-5102 | 1）**事件可追溯到来源。** 记录源设备、事件类型、事件编号、发生时间及所需的测量值、结果或原因。由能够确认结果的一方产生事件，例如 LPN 记录低电预警，作出拒绝决定的节点记录入网拒绝。<br>2）转发时保留来源及原发生时间。云端另记接收时间，无法确认发生时间时标记为未知。 | P0  | FW、网关／协议、云平台、TE |
| SR-5103 | 1）**人员状态使用有效检测结果。** 支持人员检测的型号应区分有人、无人、未知。因停测或有效数据不足而无法判断时，记录为未知。<br>2）链路失联后，平台可显示最后一次有效状态和时间，并标明当前状态未知。自动关灯应使用当前有效的无人结果。                    | P0  | FW、执行端、云平台、TE   |

| ID      | 需求描述                                                                                                                                                                      | 优先级 | 对应领域                  |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | --------------------- |
| SR-5201 | 1）**现场联动走本地路径。** 需要联动的有效事件经「LPN → 现场 BLE 链路 → 同组灯具或其他执行端」发送。<br>2）公网中断时，只要现场联动链路仍可达且规则已生效，现场联动应继续。                                                                        | P0  | FW、网关／协议、执行端、TE       |
| SR-5202 | 1）**分别确认执行端收件和实际动作。** 收件回执记录消息已收到。动作结果以执行端提供的反馈为准，验收时可现场核对灯是否实际亮起。缺少动作反馈时，记录当前能够确认的阶段。<br>2）需要收件确认的联动事件按各型号规定限次重发。达到上限仍无回执时记录确认超时。同一事件重发时，现场动作只执行一次。                      | P0  | FW、网关／协议、执行端、TE       |
| SR-5203 | 1）**云端记录走上行路径。** 需要上云的事件经「LPN → BLE 父节点 → 现场 PLC／Sub-G 主干 → 智能网关 → 云平台」发送。小程序和 Web 管理端从云平台查看记录。<br>2）分别记录父节点接管与云端入库。父节点确认接手事件后，LPN 可结束该段投递。以云端实际保存结果确认入库，平台按已掌握的结果展示送达状态。 | P0  | FW、网关／协议、云平台、微信小程序、TE |
| SR-5204 | 1）**本地通知和事件上行可独立工作。** 本地联动按现场条件触发，上行按该事件配置执行。<br>2）父节点失联时，LPN 保留待上报事件，仍可在可达的本地链路上联动。本地通知确认超时时，上行按原配置继续。                                                                   | P0  | FW、网关／协议、执行端、TE       |

## 3.3 上报方式与配置生效

| ID      | 需求描述                                                                                                                                          | 优先级 | 对应领域               |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --- | ------------------ |
| SR-5301 | 1）**逐条配置适用事件。** 按事件分别定义启用状态、是否本地通知、是否需要执行端或父节点确认，以及记录方式。记录方式包括即时上报、汇总上报、随心跳上报或仅本地记录。<br>2）各型号定义默认值和支持的选项。关键告警及配置结果等锁定项按该型号的最低上报要求执行。          | P0  | FW、网关／协议、云平台、微信小程序 |
| SR-5302 | 1）**上报节奏符合设备能力。** 在型号、权限和能量允许范围内，支持设置适用的上报间隔、汇总周期、批量条数和重发次数。关键事件按定义优先逐条发送。<br>2）汇总记录应能查到来源、统计区间、发生次数，以及该事件需要的首末值或极值。能量策略调整上报节奏时，以设备报告的实际方式为准。 | P0  | FW、网关／协议、云平台、TE    |
| SR-5303 | 1）**配置以设备实际生效为准。** 同一设备的一组配置须全部校验通过后一起生效。设备应返回生效结果、当前版本、实际设置或拒绝原因，并支持读回。<br>2）同一申请重试时结果一致。配置途中掉电时，设备恢复至最近一份完整有效的配置，平台以设备返回的实际结果更新状态。          | P0  | FW、云平台、微信小程序、TE    |
| SR-5304 | 1）关闭某个可选事件后，采样、心跳、已支持的快照及其他事件继续按各自配置运行。<br>2）现场或云端规则依赖该事件时，平台提示受影响的联动或记录。                                                                     | P0  | FW、云平台、微信小程序、TE    |

## 3.4 断链、重发与补报

| ID      | 需求描述                                                                                                                                              | 优先级 | 对应领域            |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | --- | --------------- |
| SR-5401 | 1）**LPN 保留尚未交接的事件。** 需要父节点确认的事件，发送后保留副本，收到与该事件对应的接管确认后方可释放。发送失败或确认丢失时记录失败次数，并按事件策略重发。<br>2）父节点已接管而上行中断时，由现场接管方保存待报事件，恢复后继续向上游发送，直至完成下一次确认交接或云端入库。 | P0  | FW、网关／协议、云平台、TE |
| SR-5402 | 1）**恢复后分批补报。** 实时关键事件优先。待补记录按原发生时间及其可信度整理，重发或换父时沿用原事件编号。<br>2）云端对同一事件或汇总记录只计入一次，补报归入历史记录。当前状态以最新有效数据为准，现场动作只使用当前有效的事件。                            | P0  | FW、网关／协议、云平台、TE |
| SR-5403 | 1）**按使用场景定义缓存能力。** 各型号明确可覆盖的断链时长、事件数量以及掉电后可恢复的记录范围。<br>2）缓存达到容量上限时，按各型号约定的优先级处理，优先保留关键事件及尚未完成交接的记录。                                               | P1  | HW、FW、网关／协议、TE  |
| SR-5404 | 1）缓存容量不足导致记录丢弃时，应计数。链路恢复后上报丢弃数量，供平台核对记录缺口。<br>2）验收时分别核对产生、送达及丢弃的记录，确认补报结果与丢弃计数一致。                                                                 | P1  | FW、网关／协议、云平台、TE |

## 3.5 事件清单与验收

| ID      | 需求描述                                                                                                                                               | 优先级 | 对应领域                  |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | --- | --------------------- |
| SR-5501 | 1）**各型号提供适用事件清单。** 每条记录事件名称、产生方、触发条件、重要程度、默认去向、确认要求及可配置范围。<br>2）人员与环境类可包括确认有人、确认无人、照度或温湿度达到设定阈值。能源与故障类可包括低电预警、供电切换、故障和恢复。接入与运行类可包括入网结果、换父、重启和配置结果。 | P0  | 产品、FW、网关／协议、云平台、TE    |
| SR-5502 | 1）**兼容已确认支持的在网设备。** 旧设备通过父节点转发的状态快照按其原有含义提供，新增事件记录可独立识别并查到来源、上报方式和实际配置。<br>2）按设备和接口版本核对可用字段。状态快照用于展示对应时点的状态，联动使用符合触发条件的有效事件。                       | P0  | FW、网关／协议、云平台、TE       |
| SR-5503 | 1）各型号分别定义并验证现场触发到实际动作的时延、上行送达要求、并发工况和断链可保留的事件数量。每项注明计时起止点、确认依据及适用工况。<br>2）按以下场景验收，核对设备、执行端和平台可查的处理结果。                                              | P0  | 产品、HW、FW、网关／协议、云平台、TE |

### 典型验收场景

1. **公网中断。** 将进入和离开事件设为逐条上报。中断公网但保留现场链路时，模拟有人进入再离开，按现场规则验证联动。公网恢复后，核对两条补报记录的原发生时间和现场动作次数。
2. **父节点失联或上行断链。** 分别在父节点接管前、接管后中断链路，核对由哪一端保留记录。换父或恢复后按原编号、原发生时间补报。
3. **回执丢失与重复送达。** 丢弃一次灯具收件回执或父节点接管确认后重发，核对现场动作只执行一次、云端只保存一条记录，并分别检查收件、实际动作、父节点接管和入库结果。
4. **缓存超限与掉电。** 在承诺工况内对照可恢复的事件数量。超出容量时核对关键事件保留情况与平台收到的丢弃计数。
5. **配置与旧设备兼容。** 验证关键事件锁定、配置中途掉电后的读回结果，以及旧快照和新事件同时到达时的展示与联动结果。
