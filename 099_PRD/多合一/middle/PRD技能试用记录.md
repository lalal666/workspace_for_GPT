# 澜潮负荷端智能硬件 PRD 技能试用记录

本记录用当前资料检查技能能否生成可评审的内容。场景输出为草稿，所列指标和策略需要按项目确认。

| 试用场景 | 资料锚点 | 技能应引导写出的内容 |
| --- | --- | --- |
| 审阅多合一传感器 PRD，核对各 SKU 的功能边界 | 《PRD-多合一存在传感器》2.1、2.5 | 分别记录双鉴静态存在、单 PIR 移动、温湿照度采集、红外执行。每个 SKU 的需求关联实际能力、链路和验收项。对文档中的安规声明要求按 SKU、供电形态及市场提供适用性证据。 |
| 为休眠节点补充云控和小程序状态需求 | 《低功耗传感器节点_产品研发目标与确认清单》7 节 Q1、Q7 | 将 30–60 s 响应与按心跳取件列为待决，说明对能量预算和用户反馈的影响。定义排队、下发、已发射及执行未知的状态和证据，避免由出队记录推断空调实际动作。 |
| 修订照明在重连时的历史事件处理需求 | 《T8灯事件物模型定义》4、6、7 节及 R7 | 引用 T8 物模型版本和选配范围，补齐事件时间与接收时间、失准处理和去重。将历史记录的保留与实时策略触发条件分别写明，避免从物模型已定义补报直接推断策略行为已定。 |

## 用模板推演一组需求和验收

| 需求 ID | 适用范围 | 跨端行为及状态 | 验收 ID |
| --- | --- | --- | --- |
| AC-01 | 温感红外控制器，待核对硬件与固件版本 | 建议在项目确认支持云控且没有双向状态反馈时，小程序提交后按云平台状态显示排队或下发结果。收到发射证据后显示已发射，空调实际状态保持未知。定义指令过期、超时和重复触发处理。指令接收时机与总时延口径待产品、固件和平台确认。 | VT-01 |

| 验收 ID | 需求 ID | 条件与执行 | 预期结果和证据 |
| --- | --- | --- | --- |
| VT-01 | AC-01 | 选定温感红外控制器和适配空调。记录固件、云端及小程序版本、节点休眠和网络状态。在小程序发出控制请求，比较受理、投递和红外发射时点。以受理为计时起点，以外部工装检测到发射为终点。覆盖休眠队列、成功发射、过期及各端重新打开或同步。 | 各端状态与实际阶段一致。过期处理符合确认策略，已发射阶段显示物理状态未知。保留同一指令的云端记录、工装观测和小程序画面。响应阈值、样本量、工装及支持版本随 Q1 决策确定。 |
