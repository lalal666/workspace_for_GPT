#### 一、产品概述与定位

一句话定义 · 与 PIR / 双鉴版的关系 · 双形态定位 · 产品边界

一句话定义：撕开背胶一贴即用、不接线不换电、周期感知光照度 / 温度 / 湿度并上报云端的微能量环境传感器；光照度约 10 s 内响应环境明暗变化、温湿度分钟级响应，采样周期与响应速度全程可配置；完全无光的位置插一根 USB 就能获得更强性能与更快的响应。

#### 1.1 与 PIR 移动传感器、双鉴存在传感器的关系

本产品是《微能量单 PIR 人体移动传感器 PRD v1.0》《微能量 PIR + 24G 双鉴存在传感器 PRD v2.0》的同系列换核型号：保留微能量供能、三通道上报、安装工艺、白名单、运维与能量管理全部能力，把唯一的检测核从"PIR 移动检测"替换为"光照度 + 温度 + 湿度"三路环境感知。三者的本质区别在驱动模型：PIR 是事件驱动（人一动才醒），本产品是周期驱动（定时醒来看环境），双鉴版是两者的混合。

| 维度 | 单 PIR 移动传感器（v1.0） | 双鉴存在传感器（v2.0） | 光照度·温湿度传感器（本产品 v1.0） | 

| 感知对象 | 人体移动（热源） | 移动 + 静止存在 | 环境：光照度 / 温度 / 湿度 | 

| 传感器 | 单 PIR（常开） | PIR（门控）+ 24G 雷达 | ALS 环境光 + 温湿度一体（数字） | 

| 驱动模型 | 事件驱动（PIR 常开监听） | 事件驱动 + 雷达周期扫描 | 周期驱动（定时采样，无外部事件唤醒） | 

| 响应速度 | 移动触发 ≤300 ms | 移动 ≤300 ms / 静止维持 | 光照度 ≈10 s / 温度·湿度分钟级 | 

| 核心时间参数 | 仅 T_leave | T_scan / T_radar_delay / W_verify / N_leave | 采样周期 ×3 + 变化阈值 ×3 + 上报方式 | 

| 联动出口 | 开灯 / 关灯 | 开灯 / 关灯 / 维持 | 开灯·调光·遮阳 / 空调·新风 / 除湿·排风 | 

| 适用场景 | 走廊、电梯厅、动线出入口 | 办公、会议室、需静止保持 | 照明节能、暖通联控、环境监测、能耗大屏 | 

一句话概括差异：PIR 版回答"有没有人"，本产品回答"环境是什么状态、变没变"。两者面向不同业务：PIR 驱动照明即时开关，本产品驱动照明调光/遮阳与暖通联控，并作为 EMS/能耗大屏/建筑环境的数据底座。

#### 1.2 双形态定位

| 形态 | 供能方式 | 适用场景 | 能力差异 | 

| 形态 A微能量 | 光伏 + 50F 超容 + 400 mAh 电池兜底，三源由能量管理 IC 统一管理 | 走廊、办公、大厅、靠窗区域——常态照度 ≥30 lux | 标准性能；受 5 级能量策略约束；采样周期与上报受能量底线改写 | 

| 形态 BUSB 外供 | USB 5 V 直供超容与升降压芯片，超容保持满电，电池不消耗 | 地库、机房、无窗库房——照度长期 <10 lux，但需环境监测 | 外供电高性能模式：无低电降级、可全量上报、采样周期可取最快档 | 

形态判据与 PIR 版有一个关键反转：PIR 的微能量形态要求"照度 ≥30 lux"是因为它要养 PIR 常开；本产品的光照度本身就是要测的量，因此照度低恰恰是最需要本产品工作、也是微能量最难自持的场景。无光且需监测 → 必须改形态 B，或在微能量形态下接受电池周期更换。

#### 1.3 产品边界

#### 本产品做（In Scope）

- 光照度感知：约 10 s 响应明暗变化，量程 0.01–83000 lux

- 温度感知：分钟级响应，-10 ~ +55 ℃

- 湿度感知：分钟级响应，0–100% RH

- 响应周期与速度全程可配置（采样周期 / 变化阈值 / 滞回 / 上报方式）

- 微能量与 USB 双供能，自动识别切换

- 三通道上报：本地广播联动 / 父节点上行 / 云端上报

- 44 条事件的全量定义与上报策略配置

- 2.4G 纯叶子终端，经 L2 CCO → L1 CCO 上联

- 3M 胶贴随手贴；镭雕设备码 + App 位置录入；背部轻触开关 + 运输模式

#### 本产品不做（Out of Scope）

- 不做人体 / 存在检测（无 PIR、无雷达）

- 不做气体、CO₂、PM2.5、噪声、气压等扩展环境量

- 不做高精度计量级温湿度（±0.1 ℃ / ±1% RH 级）

- 不做中继/路由；不做 Sub-G、不做 PLC；不做独立网关

- 不做摄像头、音频、身份识别

- 不做室外、雨淋；不做高温蒸汽 / 强腐蚀环境

#### 2.2 典型场景与形态选择

| 场景 | 推荐形态 | 核心用途 | 光照度采样 | 温度采样 | 特殊约束 | 

| 办公 / 靠窗区 | 微能量 | 日光调光、遮阳联动、环境监测 | 5 s（快响应） | 60 s | 靠窗照度足，可养 ALS 阈值中断 | 

| 走廊 / 楼梯间 | 微能量 | 照度联动开灯、昼夜判定 | 10 s | 300 s | 与 PIR 传感器互补：PIR 管"有人"，本产品管"够不够亮" | 

| 地下车库 / 机房 | USB 外供 | 照明调光、温湿度告警、凝露风险 | 5 s | 60 s | 无光，微能量不可行；湿度监测防凝露/防锈蚀 | 

| 暖通机房 / 配电间 | USB 外供 | 高温告警、湿度监测、节能评估 | 30 s | 60 s | 高温是设备保护主线（P0 级事件） | 

| 大厅 / 门厅 | 微能量 | 日光判定、环境舒适度 | 10 s | 300 s | 人流经停，温湿度变化慢，低频即可 | 

与 PIR 传感器的互补布点：本产品不是 PIR 的替代，而是同一张网里的"环境感知层"。典型组合——走廊里 PIR 负责"有人即开灯"，光照度·温湿度传感器负责"天亮了就别开 / 空调该不该开"。布点建议：动线出入口用 PIR，开敞区域与暖通关键点用本产品。

#### 3.2 供能路径拆解

三条路径的角色与 PIR 版完全一致，必须分清，否则会误判"开关断开后设备应该完全不工作"。

| 路径 | 走向 | 关键特性 | 

| 主能量路径 | 光伏 / 超容 / 电池 → 能量管理 IC → SW1 背部轻触开关 → Buck-Boost → 系统 | 三源统一调度输出单路；开关就切在这一路上 | 

| USB 充电路径 | USB → 锂超容（直充，不经 IC） | 现场补电与产线预充走这条，速度快 | 

| USB 直供路径 | USB → Buck-Boost → 系统（绕过 SW1） | 运输模式下插 USB 仍可工作——产线可在弹起状态完成写入与测试 | 

#### 3.3 两种供能形态的行为差异

| 项目 | 形态 A 微能量 | 形态 B USB 外供 | 

| 采样周期 | 受 5 级能量策略约束，低电档拉长采样周期 | 可取最快档（光照 1–5 s、温度 30 s） | 

| 事件上报 | 受 5 级能量策略约束，P2 可能被压缩 | 全量上报，不受限 | 

| 电池寿命顾虑 | 存在（视照度） | 无，电池完全不消耗 | 

| 充电中行为 | — | 边充边采，采样不中断 | 

| 识别与切换 | 自动识别 USB 插入/拔出，≤5 s 切换供能模式并上报 powerSource；切换过程采样不中断、不重启 | 

#### 3.4 传感窗与外观：从"无孔化"到"隐蔽传感窗"

本产品与 PIR 版外观要求的分歧点：PIR 靠"整机无孔"消除摄像头联想；本产品湿度传感器必须接触空气，温度传感器也需一定气流接触，因此无法做到绝对无孔。设计原则从"无孔"调整为"隐蔽传感窗 + 无镜头联想"。

| # | 设计要求 | 具体做法 | 要避免的观感 | 

| 1 | 透气膜窗（湿度必需） | ePTFE 防水透气膜贴于侧缘细缝，面积 ≥10 mm²；外侧做细格栅纹理，不做圆形小孔 | "麦克风孔 / 镜头" | 

| 2 | 感光面隐蔽 | ALS 置于整片半透明装饰环下，与光伏采光面同区；外表面均匀雾面 | 独立小圆窗（镜头联想） | 

| 3 | 无外露状态灯 | LED 用隐藏导光柱，仅调试模式透光，量产不可见 | 红灯常亮＝"正在录制" | 

| 4 | 表面避免镜面 | 哑光、细皮纹或细磨砂 | 镜面反光像镜头镀膜 | 

| 5 | 形态贴近"环境设施" | 圆或方圆扁平盘（Φ90×32 mm 内），视觉接近烟感/温控；白、灰双色 | "安防监控设备" | 

| 6 | USB 口与开关隐蔽 | 同置于底面凹槽、同色盖片遮蔽、与镭雕码同区 | 外露接口＝"可被改装" | 

温湿度测量精度的外观代价：透气膜窗、传感热接触、采光面朝向三者共同决定了本产品的测量可信度。若为"绝对无孔"牺牲透气，湿度读数会显著滞后、漂移、凝露失准。因此本产品承诺"无镜头、无麦克风、无摄像"，但不承诺"无孔"——这一条须写进宣传口径与隐私声明卡。

#### 4.2 唤醒窗口与父节点时隙编排

与 PIR 版的最大差异：本产品没有"外部触发随时唤醒"。PIR 靠人一进来就拉高电平唤醒设备，本产品的所有动作都发生在定时唤醒窗口内——要么是 ALS 阈值中断，要么是周期采样定时器。

| 机制 | 要求 | 说明 | 

| 唤醒窗口长度 | 100–500 ms（暂定） | 形态 B 可取上限提升下行成功率 | 

| 唤醒时刻协商 | 节点与父节点协商基准时刻与周期 | 入网或参数变更时协商 | 

| 时隙编排 | 父节点编排各子节点唤醒窗口；单父节点 ≤8 台 | 8×500 ms=4 s，相对采样周期占比很低 | 

| 窗口超时 | 无下行 → 立即继续休眠 | 不做无意义等待 | 

| 交互维持 | 有下行或有上传 → 按交互需求维持 | 需约定最长维持上限 | 

| 传感唤醒 | 仅两类：① ALS 阈值中断 ② 周期采样定时器 | 无人体事件唤醒 | 

#### 4.3 三条硬约束

| # | 约束 | 原因与影响 | 

| 1 | 不可作为中继 / 路由节点 | 中继需 7×24 常收，功耗 mA 级。入网须带 devClass=HARVEST_LEAF、canRelay=false | 

| 2 | 仅 2.4G，不接 PLC、不用 Sub-G | 无市电耦合无法做 PLC；统一 2.4G 单模 |

#### 4.4 双向暂存与失败回退

| 方向 | 机制 | 溢出处理 | 节点侧配合 | 

| 下行 | 父节点为休眠子节点暂存下行报文，唤醒窗口内投递 | 溢出则上游返回失败，云侧重试 | 窗口内未收到即继续休眠 |

#### 七、事件定义与上报配置体系

六条设计原则 · 三通道出口 · 云端四档 · 八维配置 · 全量矩阵 · 配置通道 · 仲裁 · 模板

#### 7.1 六条设计原则

- 每条事件必须有可判定的触发条件。"光照变暗"是一组明确条件：照度跨过阈值（带滞回）且持续稳定。

- 三条出口必须分开定义。开灯要快、上报要省是两个正交需求，拆成三条才能同时最优。

- 上报方式是设备行为，必须是有限枚举。设备是休眠终端，所有配置必须落在可执行档位内。

- 三级硬约束不可被配置突破：① 能量底线 ② 安全合规类（高温、凝露、传感失效、防拆必须即时且不可禁用）③ 数据完整性（缓存溢出、白名单失败、联动确认超时必须报）。

- 本地配置是受控变更，必须经云端人工确认。

- 聚合不是丢弃，是延迟。聚合类事件仍完整记录，周期到达打包上报。

#### 7.2 三通道出口模型

| 通道 | 标识 | 目的 | 典型时延 | 确认语义 | 失败处理 | 

| D1 本地广播 | LB | 立即让灯/执行器动作，不等网络、不等云 | ≤300 ms（泛洪，≤4 跳） | 设备广播后即休眠，指令副本交父节点代确认与补发 | 父节点补发 2 次；仍无确认 → 上报 E605 | 

| D2 父节点上行 | UL | 把事件交进网络，保证不丢 | 1 个唤醒窗口内（100–500 ms） | 父节点 ACK，代表事件已进入暂存队列 | 未 ACK 则本地保留、下次唤醒重传 | 

| D3 云端上报 | CL | 可运营、可统计、可追溯 | I ≤1 s／A 15 min–24 h／H 300–1800 s／L 不上报 | 父节点 ACK 即视为设备侧完成投递 | 按 A 档缓存、补报；溢出报 E508 | 

本产品特别提醒：环境量（温湿度）是慢变量、强周期性、低价值密度，默认应大量走 A/H 档聚合，只有阈值穿越与越限告警走 I 档。切勿把温湿度按秒级即时上报——那会瞬间吃光能量预算，且云端没有任何运营价值。

#### 7.3 云端上报四档

| 标识 | 方式 | 时延 | 设备行为 | 适用 | 

| I | 即时 Immediate | ≤1 s（P1）≤300 ms（P0 场景） | 发生立即组帧发出，按配置重传 0–2 次 | 安全类、越限告警、必须实时可见的主事件 | 

| A | 聚合 Aggregate | 15 min / 30 min / 1 h / 2 h / 6 h / 12 h / 24 h | 写入环形缓存，到期打包上报 | 环境量统计、诊断类 |

#### 7.7 配置优先级与冲突仲裁

- ① 能量底线（最高）：低电强制拉长采样周期、压缩上报。L3 起 P2 转 H；L4 起 P2 停发；L5 仅 P0。

- ② 安全与完整性硬约束：19 条不可禁用事件强制 I 档，重传 ≥1 次。

- ③ 云端基线配置：项目/楼栋/楼层/群组/单点五级下发。

- ④ 本地蓝牙配置：需云端人工确认；不可突破 ①②。

两个不承诺项必须写进规格书：① 本产品不承诺计量级温湿度精度（±0.3 ℃ / ±2% RH 是监测级，非 ±0.1 ℃ 计量级）；② 温度/湿度的"响应时间"受外壳热时间常数与气流影响，静滞无对流环境下响应会慢于标称值。凡需快速、高精度温湿度的场景，应改选有线计量型传感器。

#### 九、能量预算与续航模型

本章是本产品区别于 PIR 版的核心：如何用微能量养活"10s 级快响应"。

核心矛盾与结论：光照度"10 s 响应"不能靠 MCU 每 5 s 定时唤醒采样实现——那意味着每天 17280 次唤醒，即使每次 50 ms@5 mA，日均也需约 120 µA，直接吃光全部能量预算。必须用低功耗 ALS 的"阈值中断"做硬件门控：ALS 以 <1 µA 连续监控，只有光照变化跨过设定阈值才拉中断唤醒 MCU。这与 PIR 版的"PIR 常开 + 门控"是同一哲学，但载体从"模拟 PIR + 比较器"换成"数字 ALS 阈值中断"。温度/湿度是慢变量，定时采样即可，能耗可忽略。

#### 9.1 双态功耗模型

| 耗能项 | 无变化态 | 变化频繁态 | 说明 | 

| ALS 阈值监控（常开） | <1 µA | <1 µA | 低功耗数字 ALS 连续监控，超阈值才拉 INT | 

| MCU 休眠 | 1–3 µA | 1–3 µA | 深度休眠 | 

| 温湿度定时采样（折算） | 0.3–0.8 µA | 0.3–0.8 µA | 温度 60 s / 湿度 300 s，每次 ~几十 ms | 

| 光照变化上报（折算） | 0.2 µA | 2–5 µA | 按 0.28 µAh/次，变化频次决定 | 

| 超容漏电 | 2 µA | 2 µA | 器件固有 | 

| IC + DC-DC 静态 | 2.3 µA | 2.3 µA | IC 300 nA + DC-DC 约 2 µA | 

| 合计 | 约 9–13 µA | 约 11–20 µA | 目标：无变化 ≤13、频繁 ≤20 | 

与 PIR 版的功耗对比：本产品省掉了 PIR 常开（2–5 µA），但新增 ALS 阈值监控（<1 µA）与温湿度定时采样（0.3–0.8 µA），且光照频繁变化时上报能耗会走高。净效果：无变化态两者接近（约 9–13 µA），但本产品在光照频繁穿越时会冲高到 20 µA——这是"快响应"的必然代价，也是"响应速度可配置"存在的根本原因：用户可在"响应快→能耗高"与"响应慢→能耗低"之间权衡。

#### 十、采样逻辑与时序

#### 10.1 核心时间参数

#### 10.2 "响应速度"的三维拆解（核心设计）

本产品的"响应速度可配置"不是单一旋钮，而是三个正交维度的组合：

| 维度 | 含义 | 配置项 | 对响应的影响 | 对能耗的影响 | 

| ① 采样周期 | 多久"看一次" | luxSamplePeriod / tempSamplePeriod / humiSamplePeriod | 决定"发现变化"的速度下限 | 周期越短，ALS 中断与温湿度采样能耗越高 | 

| ② 判定阈值 + 滞回 | 多大变化才"算变化" | luxDelta / tempDelta / humiDelta + 滞回 | 阈值越小越灵敏，越易"响应" | 阈值越小，穿越越频繁，上报能耗越高 | 

| ③ 上报方式 | 变化后"多快说出来" | I / A / H / L 四档 | I 档即时，A/H 档延迟 | I 档最贵，A/H 档省 | 

因此"响应速度" = f(采样周期, 阈值, 上报方式)。三者组合出从"快响应（1 s 采样 + 5% 阈值 + I 档）"到"极限省电（60 s 采样 + 50% 阈值 + A 档）"的连续谱系。

#### 10.3 光照度 10s 响应的完整时序

- 
  照度

  照度阶跃（明→暗）

- 
  时间

  ~ms 级

  ③ 采样+判定

  ④ 上报/联动

为什么是"硬件门控"而不是"MCU 轮询"：若 MCU 每 5 s 醒来采一次光照度，一天 17280 次唤醒，每次即使 50 ms@5 mA，日均能耗约 120 µA，远超预算。改用带阈值中断的 ALS（OPT3001 / LTR-329 类，睡眠 <1 µA），ALS 自己连续监控照度，只有光照变化跨过 luxDelta 才拉中断，MCU 平时深度休眠。这样"10 s 响应"的能量代价从 120 µA 降到 <2 µA——这是本产品能否在微能量下成立的决定性技术选择，M0 阶段必须锁定 ALS 选型。

#### 11.1 安装姿态与朝向

| 姿态 | 推荐高度/角度 | 适用场景 | 朝向要求 | 

| 顶装 | 吊顶 2.6–3.2 m，垂直向下 | 办公大开间、走廊 | 感光面朝下/朝灯源；透气膜窗朝下 |

#### 11.3 安装流程（顺序不可颠倒）

- 取件：按箱取件。

- 能量核查：检查超容电压；<3 V 则 USB 补电至 3.5 V 再装（<10 min）。

- 基材判定：对照附着面清单；乳胶漆面做拉拔试验。

- 朝向判定：确认感光面与透气膜窗朝向（见 11.1）。

- 粘贴：酒精擦拭 → 干透 → 撕膜 → 压合 ≥10 s。

- 贴装下压通电：压合使背部开关导通、上电。必须先通电再扫码。

- 扫码绑定：扫镭雕码 → 录入位置 → 选姿态与倾角 → 提交。

- 白名单校验：等待云端返回。

- 入网确认 + 三通道自检：App 显示上线，并回读 lux/temp/humi 三值确认测量正常。

- 分批自检：2 h 后平台出报告（含能量基线、三通道功能、朝向评估）。

本产品独有的安装验收项：入网后必须回读三通道实时值并人工确认量级合理（如 lux 在 0–100000 内、temp 在 -10–55 内、humi 在 0–100 内且随环境变化）。若某通道恒定或超量程，可能传感器未焊好/未标定/朝向错误，应现场纠正。这一条决定了环境数据底座的可信度。

#### 15.2 术语

| 术语 | 说明 | 

| 响应速度 | 从环境量发生可感知变化，到设备判定并响应（上报/联动）的时长，由采样周期 × 阈值 × 上报方式三维决定 | 

| 采样周期 | 设备多久唤醒采集一次环境量（luxSamplePeriod / tempSamplePeriod / humiSamplePeriod） | 

| 变化阈值 + 滞回 | 多大的变化才触发"响应"；滞回防止阈值附近抖动 | 

| 阈值中断门控 | 低功耗 ALS 连续监控，只有变化跨阈值才拉 INT 唤醒 MCU——10s 响应的能量前提 | 

| 外壳热时间常数 τ_therm | 外壳使内部温度传感器跟随环境温度变化所需的时间常数，温度分钟级响应的硬件前提 | 

| 上报方式 I/A/H/L | 即时 / 聚合 / 随心跳 / 仅本地 | 

| 形态 A / 形态 B | 微能量供能 / USB 长期供电 | 

| 四层配置仲裁 | 能量底线 > 安全硬约束 > 云端基线 > 本地配置 | 

核心结论：本产品把 PIR 移动传感器的"事件驱动"换成"周期驱动"，回答的问题从"有没有人"变为"环境是什么状态、变没变"。

① 传感换核：PIR 常开 → ALS 阈值中断（光照）+ 温湿度定时采样。光照度 10 s 响应、温湿度分钟级响应。

② 响应可配置：响应速度 = 采样周期 × 变化阈值 × 上报方式，三维正交可配，在"响应快→能耗高"与"响应慢→能耗低"之间连续权衡。

③ 关键边界：光照度 10 s 响应必须靠"ALS 阈值中断门控"实现，靠 MCU 轮询会吃光预算；温度分钟级响应受外壳热时间常数制约；微能量形态在无光场景不可行，须改 USB 外供。
