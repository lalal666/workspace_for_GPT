一、产品概述与定位

一句话定义 · 与 PIR / 双鉴版的关系 · 双形态定位 · 产品边界

一句话定义：撕开背胶一贴即用、不接线不换电、周期感知光照度 / 温度 / 湿度并上报云端的微能量环境传感器；光照度约 10 s 内响应环境明暗变化、温湿度分钟级响应，采样周期与响应速度全程可配置；完全无光的位置插一根 USB 就能获得更强性能与更快的响应。

1.1 与 PIR 移动传感器、双鉴存在传感器的关系

本产品是《微能量单 PIR 人体移动传感器 PRD v1.0》《微能量 PIR + 24G 双鉴存在传感器 PRD v2.0》的同系列换核型号：保留微能量供能、三通道上报、安装工艺、白名单、运维与能量管理全部能力，把唯一的检测核从"PIR 移动检测"替换为"光照度 + 温度 + 湿度"三路环境感知。三者的本质区别在驱动模型：PIR 是事件驱动（人一动才醒），本产品是周期驱动（定时醒来看环境），双鉴版是两者的混合。

维度单 PIR 移动传感器（v1.0）双鉴存在传感器（v2.0）光照度·温湿度传感器（本产品 v1.0）
感知对象人体移动（热源）移动 + 静止存在环境：光照度 / 温度 / 湿度
传感器单 PIR（常开）PIR（门控）+ 24G 雷达ALS 环境光 + 温湿度一体（数字）
驱动模型事件驱动（PIR 常开监听）事件驱动 + 雷达周期扫描周期驱动（定时采样，无外部事件唤醒）
响应速度移动触发 ≤300 ms移动 ≤300 ms / 静止维持光照度 ≈10 s / 温度·湿度分钟级
核心时间参数仅 T_leaveT_scan / T_radar_delay / W_verify / N_leave采样周期 ×3 + 变化阈值 ×3 + 上报方式
联动出口开灯 / 关灯开灯 / 关灯 / 维持开灯·调光·遮阳 / 空调·新风 / 除湿·排风
适用场景走廊、电梯厅、动线出入口办公、会议室、需静止保持照明节能、暖通联控、环境监测、能耗大屏

一句话概括差异：PIR 版回答"有没有人"，本产品回答"环境是什么状态、变没变"。两者面向不同业务：PIR 驱动照明即时开关，本产品驱动照明调光/遮阳与暖通联控，并作为 EMS/能耗大屏/建筑环境的数据底座。

1.2 双形态定位

形态供能方式适用场景能力差异
形态 A
微能量		光伏 + 50F 超容 + 400 mAh 电池兜底，三源由能量管理 IC 统一管理走廊、办公、大厅、靠窗区域——常态照度 ≥30 lux标准性能；受 5 级能量策略约束；采样周期与上报受能量底线改写
形态 B
USB 外供		USB 5 V 直供超容与升降压芯片，超容保持满电，电池不消耗地库、机房、无窗库房——照度长期 <10 lux，但需环境监测外供电高性能模式：无低电降级、可全量上报、采样周期可取最快档
形态判据与 PIR 版有一个关键反转：PIR 的微能量形态要求"照度 ≥30 lux"是因为它要养 PIR 常开；本产品的光照度本身就是要测的量，因此照度低恰恰是最需要本产品工作、也是微能量最难自持的场景。无光且需监测 → 必须改形态 B，或在微能量形态下接受电池周期更换。

1.3 产品边界

本产品做（In Scope）

  • 光照度感知：约 10 s 响应明暗变化，量程 0.01–83000 lux
  • 温度感知：分钟级响应，-10 ~ +55 ℃
  • 湿度感知：分钟级响应，0–100% RH
  • 响应周期与速度全程可配置（采样周期 / 变化阈值 / 滞回 / 上报方式）
  • 微能量与 USB 双供能，自动识别切换
  • 三通道上报：本地广播联动 / 父节点上行 / 云端上报
  • 44 条事件的全量定义与上报策略配置
  • 2.4G 纯叶子终端，经 L2 CCO → L1 CCO 上联
  • 3M 胶贴随手贴；镭雕设备码 + App 位置录入；背部轻触开关 + 运输模式

本产品不做（Out of Scope）

  • 不做人体 / 存在检测（无 PIR、无雷达）
  • 不做气体、CO₂、PM2.5、噪声、气压等扩展环境量
  • 不做高精度计量级温湿度（±0.1 ℃ / ±1% RH 级）
  • 不做中继/路由；不做 Sub-G、不做 PLC；不做独立网关
  • 不做摄像头、音频、身份识别
  • 不做室外、雨淋；不做高温蒸汽 / 强腐蚀环境

3.4 传感窗与外观：从"无孔化"到"隐蔽传感窗"

本产品与 PIR 版外观要求的分歧点：PIR 靠"整机无孔"消除摄像头联想；本产品湿度传感器必须接触空气，温度传感器也需一定气流接触，因此无法做到绝对无孔。设计原则从"无孔"调整为"隐蔽传感窗 + 无镜头联想"。

4.2 唤醒窗口与父节点时隙编排

与 PIR 版的最大差异：本产品没有"外部触发随时唤醒"。PIR 靠人一进来就拉高电平唤醒设备，本产品的所有动作都发生在定时唤醒窗口内——要么是 ALS 阈值中断，要么是周期采样定时器。

机制要求说明
唤醒窗口长度100–500 ms（暂定）形态 B 可取上限提升下行成功率
唤醒时刻协商节点与父节点协商基准时刻与周期入网或参数变更时协商
时隙编排父节点编排各子节点唤醒窗口；单父节点 ≤8 台8×500 ms=4 s，相对采样周期占比很低
窗口超时无下行 → 立即继续休眠不做无意义等待
交互维持有下行或有上传 → 按交互需求维持需约定最长维持上限

7.1 六条设计原则

  • 每条事件必须有可判定的触发条件。"光照变暗"是一组明确条件：照度跨过阈值（带滞回）且持续稳定。
  • 三条出口必须分开定义。开灯要快、上报要省是两个正交需求，拆成三条才能同时最优。
  • 上报方式是设备行为，必须是有限枚举。设备是休眠终端，所有配置必须落在可执行档位内。
  • 三级硬约束不可被配置突破：① 能量底线 ② 安全合规类（高温、凝露、传感失效、防拆必须即时且不可禁用）③ 数据完整性（缓存溢出、白名单失败、联动确认超时必须报）。
  • 本地配置是受控变更，必须经云端人工确认。
  • 聚合不是丢弃，是延迟。聚合类事件仍完整记录，周期到达打包上报。

九、能量预算与续航模型

本章是本产品区别于 PIR 版的核心：如何用微能量养活"10s 级快响应"。
核心矛盾与结论：光照度"10 s 响应"不能靠 MCU 每 5 s 定时唤醒采样实现——那意味着每天 17280 次唤醒，即使每次 50 ms@5 mA，日均也需约 120 µA，直接吃光全部能量预算。必须用低功耗 ALS 的"阈值中断"做硬件门控：ALS 以 <1 µA 连续监控，只有光照变化跨过设定阈值才拉中断唤醒 MCU。这与 PIR 版的"PIR 常开 + 门控"是同一哲学，但载体从"模拟 PIR + 比较器"换成"数字 ALS 阈值中断"。温度/湿度是慢变量，定时采样即可，能耗可忽略。

因此"响应速度" = f(采样周期, 阈值, 上报方式)。三者组合出从"快响应（1 s 采样 + 5% 阈值 + I 档）"到"极限省电（60 s 采样 + 50% 阈值 + A 档）"的连续谱系。

10.3 光照度 10s 响应的完整时序

为什么是"硬件门控"而不是"MCU 轮询"：若 MCU 每 5 s 醒来采一次光照度，一天 17280 次唤醒，每次即使 50 ms@5 mA，日均能耗约 120 µA，远超预算。改用带阈值中断的 ALS（OPT3001 / LTR-329 类，睡眠 <1 µA），ALS 自己连续监控照度，只有光照变化跨过 luxDelta 才拉中断，MCU 平时深度休眠。这样"10 s 响应"的能量代价从 120 µA 降到 <2 µA——这是本产品能否在微能量下成立的决定性技术选择，M0 阶段必须锁定 ALS 选型。
