一、产品概述与定位

一句话定义：撕开背胶一贴即用、不接线不换电、检测到人体移动即联动开灯的微能量移动传感器；完全无光的位置插一根 USB 就能获得更强性能。

1.1 与双鉴存在传感器的关系

本产品是《微能量 PIR + 24G 双鉴存在传感器 PRD v2.0》的同系列降配型号：保留 PIR 移动检测、微能量供能、光照四用途、三通道上报、安装工艺等全部能力，移除 24G 雷达通道与"静止存在检测"。一句话概括差异：双鉴版"人坐那儿不动也不会关灯"，本产品"人一直不动、过了无人延时就关灯"。

维度双鉴存在传感器（v2.0）单 PIR 移动传感器（本产品 v1.0）
检测能力移动检测 + 静止存在（雷达延迟确认维持）仅移动检测，无静止存在能力
传感器PIR（门控）+ 24G 雷达（延迟确认）单 PIR
静坐关灯不会——雷达维持"有人"会——静坐满 T_leave 后判无人关灯
检测逻辑PIR 门控 + AND 校验 + 回滚 + N_leave 多次判决PIR 触发 + 无人延时 T_leave（每次触发重置计时器）
关键时间参数T_scan / T_radar_delay / W_verify / N_leave仅 T_leave（无人延时）
成本 / 功耗雷达模组 + 门控逻辑，整机功耗较高省掉雷达模组与扫描能耗（约省 25% 日均能耗）
适用场景办公、会议室、需静止保持的场景走廊、电梯厅、大厅、区域出入口、地库、楼梯间等移动型动线场景
必须写进投标与规格书的边界：本产品不承诺"静止存在检测"——人在探测区内持续静坐（无任何肢体移动）超过 T_leave 会被判为"无人"并关灯。这是纯 PIR 方案的固有特性，不是缺陷。凡需要"静止保持"（单独值班室、ICU 陪护、长时间静坐办公位）的场景，应改选双鉴存在传感器或常供电 + 常开雷达方案。

1.3 产品边界

本产品做（In Scope）

  • 单 PIR 人体移动检测，触发即联动开灯
  • 无人延时 T_leave 关灯（10 s–30 min 可配，断电保持）
  • 微能量与 USB 双供能，自动识别切换
  • 光照四用途：联动 / 安装质检 / 免开灯 / 灯具故障辅助判断
  • 43 条事件的全量定义与三通道上报策略配置
  • 2.4G 纯叶子终端，经 L2 CCO → L1 CCO 上联
  • 3M 胶贴随手贴；镭雕设备码 + App 位置录入
  • 背部轻触开关：贴墙下压上电、拿起弹起延迟断电并产生脱落告警（运输模式）
  • 无孔化外观

本产品不做（Out of Scope）

  • 不做摄像头、音频采集、身份识别
  • 不做 24G 雷达，不做静止存在检测
  • 不做双鉴融合 / 进入回滚 / 离开多次判决
  • 不做中继/路由；不做 Sub-G、不做 PLC
  • 不做独立网关
  • 不做距离分档 / 多人计数 / 活动强度分级
  • 不做室外、雨淋；不做粗糙易脱落墙面

场景选择原则（比双鉴版更需强调）：本产品只适合人流有明显移动的动线场景。凡是"人会在固定位置长时间静止"（办公位、ICU、值班室、影音室、卫生间隔间）的场景，纯 PIR 会因静坐关灯而被投诉——销售布点时应主动识别并升级为双鉴存在传感器，而不是把 T_leave 无脑调到 30 min（那样节能率会大幅回落）。

3.2 供能路径拆解

三条路径的角色必须分清，否则会误判"开关断开后设备应该完全不工作"。

路径走向关键特性
主能量路径光伏 / 超容 / 电池 → 能量管理 IC（三源统一管理）→ SW1 背部轻触开关 → Buck-Boost → 系统三源由一个 IC 统一调度，输出单路；开关就切在这一路上
USB 充电路径USB → 锂超容（直充，不经 IC）现场补电与产线预充走这条，速度快、不受 IC 充电逻辑限制
USB 直供路径USB → Buck-Boost → 系统（绕过 SW1）运输模式（开关弹起断开）下插 USB 设备仍能工作——产线可在弹起（未贴墙）状态完成身份写入与测试
USB 旁路这个设计很实用。产线可以在"已进入运输模式"（开关弹起、未贴墙）的状态下直接插 USB 完成写入、校验、测试，最后拔线包装——无需任何开关动作，贴装即上电。

3.4 覆盖角：触发角 120°

本产品只有一种角度职责：PIR 有效触发角 120°（全角）。它决定了"这个点位能发现多大范围的人"，是产品的对外承诺值。没有雷达，因此不存在"保持角"。

区域（以安装点垂线为 0°）PIR 触发角（全角 120°）实际能力
0°–60°（核心区）可触发能发现移动热源，触发开灯与状态翻转
>60°（环外）不可触发无检测能力；人若只在该区域活动，永远不会被发现

对外表述规范：规格书写"有效探测角 120°（触发）"。销售布点时按 120° 计算覆盖，环外不作设计覆盖使用。

4.4 双向暂存与失败回退

方向机制溢出处理节点侧配合
下行父节点为休眠子节点暂存下行报文，唤醒窗口内投递溢出则上游返回失败，云侧重试窗口内未收到即继续休眠
本地广播不经树形路径：2.4G 泛洪组播直达同群组灯节点，TTL ≤4父节点未收到灯侧确认 → 补发 2 次，仍失败由父节点上报 E606设备广播后立即休眠，不等待确认；灯侧按 evtSeq 去重执行并回短 ACK
上行父节点接收后暂存再转发，防父节点离线丢报文超暂存深度则通知发送失败，节点写入事件缓存，下次唤醒重传"未确认→本地缓存→重传"；缓存满时上报丢弃条数

上行暂存比下行更重要：下行可重发，上行丢失是事件永久丢失。建议"父节点 ACK 后才删本地缓存"的两阶段语义。

七、事件定义与上报配置体系

本章是全文核心依据：43 条事件逐条给出定义（触发条件 + 含义），并把事件出口拆成三条独立通道——本地广播、父节点上行、云端上报——分别规定默认方式、周期与可禁用性。研发可直接按此实现，测试可直接按此验收。

7.1 六条设计原则

  1. 每条事件必须有可判定的触发条件。"有人离开"是一组明确条件：T_leave 计时器到期（期间无 PIR 触发）。
  2. 三条出口必须分开定义，不能用一个"上报方式"字段笼统表达。开灯要快、上报要省是两个正交需求，拆成三条才能同时最优。
  3. 上报方式是设备行为，必须是有限枚举。设备是休眠终端，所有配置必须落在可执行的有限档位内。
  4. 三级硬约束不可被配置突破。① 能量底线 ② 安全合规类（防拆、滞留、PIR 失效必须即时且不可禁用）③ 数据完整性（缓存溢出、白名单失败、联动确认超时必须报）。
  5. 本地配置是受控变更，必须经云端人工确认。生效后进入"待确认"态，72 h 未确认告警，7 天自动回退。
  6. 聚合不是丢弃，是延迟。聚合类事件仍完整记录在本地缓存，周期到达打包上报；期间若发生更高优先级事件，打包一并提前发送。

11.5 安装流程（顺序不可颠倒）

  1. 取件：按箱取件。

  4. 粘贴：酒精擦拭 → 干透 → 撕膜 → 压合 ≥10 s。
  5. 贴装下压通电：撕膜后用力压合，背部轻触开关被墙面下压导通、设备上电。必须先通电再扫码——设备通电才能入网，扫码登记时才能即时校验在线状态。

  8. 入网确认：App 显示上线即完成。

15.2 术语

有效触发角PIR 能可靠触发"有人进入"的水平角度（120°），即产品对外承诺的探测角

形态 A / 形态 B微能量供能 / USB 长期供电
核心结论：本产品是把双鉴存在传感器的"移动检测"能力独立出来做成的降配型号，所有设计取舍都围绕一个前提——它只对移动负责，不对静止负责。

① 逻辑极简。没有雷达、没有双鉴融合、没有回滚，只有一个 T_leave 计时器：PIR 触发 → 开灯并重置计时器；计时器到期 → 关灯。研发与测试的复杂度大幅下降。

② 省电更彻底。省掉雷达扫描的约 60 µAh/日，整机日均约 180 µAh，平衡照度降至约 40 lux，自持能力更强。

③ 边界必须写进投标文档与规格书：本产品不承诺静止存在检测，人静止不动超过无人延时会关灯；触发角 120° 之外环带不能作为设计覆盖。凡需静止保持的场景，请改选双鉴存在传感器。
